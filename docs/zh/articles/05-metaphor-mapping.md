# 05 梦境的隐喻映射：编译、运行、调试、提交、部署

梦境编程用一套隐喻来描述传统开发的每个环节。这套隐喻并不只是修辞，它为每个环节规定了不同的意义，也决定了开发者在该环节应当如何行动。下面把五个主要环节逐一对照。

编译对应的是"在潜意识中编译"。传统编译器读取源代码，检查语法，生成机器码。梦境编程中，编译由睡眠中的大脑完成。它不一定严格遵守语法，而是把白天的印象整理成可以运行的结构。因此，编译的产物往往比源代码更完整，也更模糊，有时还会补充一些原本没有写下的部分。

运行对应的是"在不存在中运行"。程序在梦中执行，但梦里没有真实的硬件，也没有真实的输入输出。这让运行变得没有边界：内存似乎无限，网络请求总是成功，异步回调在醒来之前都会完成。当然，这些都是隐喻。在本项目的实现中，`dc run` 会真实地执行脚本，只是它的输出会以 segfault 结束。

调试对应的是"解梦"。传统调试是找出错误的原因并修复它，梦境编程则要求开发者去理解错误的象征意义。比如，一个空指针异常可能意味着你在梦里找不到某样东西，一个栈溢出可能意味着你在梦里反复走同一条楼梯。这种解读并不保证准确，但它迫使开发者从更高的层次思考问题。

提交对应的是"入睡即提交"。传统提交是一个主动的动作，开发者决定什么时候保存进度。梦境编程则把提交放在入睡的时刻，意味着开发者在离开工作状态的那一刻，把当天的成果交给潜意识。醒来后如果还记得，可以再做一次真正的提交。

部署对应的是"醒来并假装什么都没发生"。部署是把代码交给真实的用户，梦境编程则要求开发者在醒来后保持平静，不要急于把梦里的结果带到现实中。这个隐喻强调的是边界感：梦的结果属于梦，现实的结果需要另外验证。

这五个隐喻构成了一个闭环。白天提出想法，夜里编译和运行，醒来后解读，然后决定是否提交和部署。每个环节都有明确的边界，也都有明确的动作。

理解这套映射，有助于在团队中沟通。当有人说"我今晚要在梦里编译一下"，其他人就能理解他的意思：他把编译的工作交给了睡眠，并且会在醒来后检查结果。隐喻因此成为一种共享的语言，让整个团队的工作节奏保持一致。
