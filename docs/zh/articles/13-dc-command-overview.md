# 13 dc 命令总览

`dc` 是梦境编程的命令行工具。它把整个流程拆成几个独立的命令，每个命令对应流程中的一个环节。理解这些命令的分工，是使用 `dc` 的基础。

目前有六个命令。`sleep` 标记入睡，检查睡眠时长。`wake` 标记醒来，输出段错误。`run` 执行一个梦境脚本。`check` 只检查脚本的语法。`eval` 执行一行代码。`version` 和 `help` 分别显示版本和帮助信息。

按照流程的顺序，它们的使用顺序大致如下：白天用 `check` 检查脚本；入睡前用 `sleep` 标记睡眠；醒来后用 `wake` 确认醒来；需要时用 `run` 或 `eval` 在白天做一些验证。注意，`run` 和 `eval` 不一定只在白天使用，它们也可以用来检查昨晚的脚本是否仍然能运行。

命令的参数设计遵循一个简单的原则：能省略的参数都可以省略，能给出默认值的参数都给出默认值。例如 `sleep` 不带参数时默认睡八小时，`run` 只需要一个文件路径，其余参数会被传给脚本的 `argv`。这种设计让常用的操作尽量简短。

所有命令都通过退出码表示结果。成功时退出码为 0，用法错误为 2，睡眠时长不足为 1，文件找不到为 3，脚本执行出错为 4。这种约定让 `dc` 可以被脚本和 CI 调用。例如，CI 中的冒烟测试就是通过检查退出码来判断睡眠下限是否被正确执行的。

输出的风格也保持统一。正常的信息输出到标准输出，错误信息输出到标准错误。脚本的 `print` 输出只属于脚本本身，`dc` 不会在其中夹带额外的信息。这让 `dc run` 的输出可以直接被管道处理，例如 `dc run dreams/fib.dc | grep fib`。

`dc` 没有交互式的 REPL，也没有配置文件。它的行为完全由命令行参数和脚本本身决定。这种无状态的设计有利于复现：同样的命令和同样的脚本，在任何机器上都应当产生同样的输出。

最后，命令的名字本身也是梦境隐喻的一部分。`sleep` 和 `wake` 是流程中最具仪式感的两个命令，它们的名字直接来自睡眠和醒来。其他命令则更偏向工具性，它们的存在是为了让白天的工作和夜晚的梦境之间保持衔接。
