# 06 白天：写下梦境脚本的方法

梦境编程的第一步发生在白天。它的目标不是写出完美的代码，而是把意图写清楚，让潜意识在夜里有足够的线索去推演。因此，白天的写作需要遵循一些不同于常规开发的习惯。

首先，梦境脚本应当短。一个梦境脚本通常只做一件事：定义一个入口，描述一组关键的步骤，然后结束。太长的脚本会让潜意识难以抓住重点，醒来后也很难回忆起其中的细节。本项目的 `dreams/main.dc` 只有二十多行，它展示了一个典型的梦境脚本应有的规模。

其次，脚本应当用清晰的名字描述意图。函数名、变量名和模块名都是潜意识的线索。比如 `compile`、`run`、`commit` 这样的名字，会让人在醒来后很快理解每一步的目的。相反，过于抽象的名字，比如 `x`、`handle`，会让梦境失去方向。

第三，脚本中可以保留一些刻意留白的地方。梦境编程允许开发者写下"这里还不知道"的部分，让潜意识去补充。这种留白不是偷懒，而是一种有意识的设计。它承认白天的认知是有限的，并把未知的部分交给夜晚。

第四，写完之后，应当用 `dc check` 做一次语法检查。这一步是白天唯一的验证动作。它确保脚本至少能被解析，避免因为一个括号没有闭合而浪费整晚的睡眠。注意，`dc check` 只检查语法，不检查语义，也不会运行脚本。

第五，写完之后，应当主动关掉编辑器。这是一个象征性的动作，也是一个实际的约束。关掉编辑器意味着结束白天的工作，也意味着不再继续修改脚本。很多人在这一步会忍不住再看一眼，但梦境编程要求克制：脚本一旦交给睡眠，就不应该在白天反复修改。

白天的写作还有一个常被忽视的要点：记录你的预期。在入睡前，可以在脚本旁边写下一两句话，说明你希望醒来后看到什么。这些话不会被执行，但它们会成为醒来后解读的参照。

总之，白天的任务是把梦的起点准备好。脚本要短，名字要清楚，留白要有意义，检查要做，然后放手。
