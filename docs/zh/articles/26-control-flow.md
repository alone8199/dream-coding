# 26 控制流：break、continue 与 return 的实现

控制流决定了程序的执行顺序。`dc` 提供了 `if`、`while`、`for` 三种结构，以及 `break`、`continue` 和 `return` 三个跳转语句。前三者的语义直观，后三者的实现方式值得单独讨论。

`if` 语句根据条件的真假选择执行哪个分支。条件使用通用的真假规则，因此空列表和零都会被视为假。`if` 可以带有 `else`，也可以连续使用 `else if` 形成多路分支。这些结构在求值器中直接映射为条件判断，没有特殊的复杂性。

`while` 语句在条件为真时反复执行循环体。每次循环开始前，求值器都会重新计算条件。`for` 语句则遍历一个可迭代对象，它可以是列表、字符串或字典。字符串会按字节逐个遍历，对于中文等非 ASCII 文字，一个字符可能占据多个字节，因此需要注意这一点。字典会按键逐个遍历。`for` 的循环变量在每次迭代中都是一个新的绑定，这一点我们在环境的文章中已经提到。

`break` 和 `continue` 的实现依赖于 C++ 的异常机制。当求值器执行到 `break` 时，它会抛出一个特殊的异常对象。循环的执行代码捕获这个异常，然后结束循环。`continue` 的做法类似，只是捕获后会跳过本次迭代，进入下一次。这种实现的好处是逻辑清晰：跳转的意图直接对应到异常的抛出和捕获，不需要在每一层语句中手动检查标志位。

`return` 的实现也使用异常。当求值器执行到 `return` 时，它会抛出一个携带返回值的异常。函数调用的代码捕获这个异常，取出返回值作为调用的结果。如果函数体正常结束而没有遇到 `return`，调用的结果就是空值。

使用异常实现跳转有一个需要注意的代价：异常的抛出和捕获比普通的函数返回慢得多。对于梦境脚本来说，循环和函数调用的次数通常不多，这个代价可以接受。如果将来需要处理大量的循环，可以考虑改用返回状态码的方式。

`break`、`continue` 和 `return` 都有作用范围的限制。在循环之外使用 `break` 或 `continue` 会报语法错误；在函数之外使用 `return` 同样会报语法错误。这些检查在运行时完成，错误信息会指出具体的行号，帮助开发者快速定位问题。

需要说明的是，上面关于 `break` 和 `continue` 的规则在函数体内目前并不完全成立。函数体内的 `break` 或 `continue` 还不会被拒绝，跳转会穿过函数边界，影响调用者所在的循环。这是当前版本已知的缺陷，计划在后续版本中修正。

需要特别提醒的是，异常机制不会跨越模块边界。如果模块的顶层代码中出现了 `return`，它会被转换为语法错误，而不是让导入者的函数提前返回。这保证了模块的执行不会意外地影响外部的控制流。

总之，`dc` 的控制流实现以简单为主要目标。它用异常来表达跳转，用环境来表达作用域，用递归来执行语句。这些选择让代码的每一部分都可以被直接对应到语言的语义，也让开发者能够快速理解脚本的执行路径。
