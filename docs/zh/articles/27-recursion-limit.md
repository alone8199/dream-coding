# 27 调用深度限制与 stack overflow in subconscious

递归是一种强大的编程技巧，但它也有一个明显的风险：如果递归没有正确地结束，调用栈会不断增长，最终耗尽内存。在 `dc` 中，这种情况会以一个特别的错误出现：`RecursionError: stack overflow in subconscious`。

这个错误的来源是调用深度限制。`dc` 的解释器维护一个计数器，记录当前正在进行的函数调用层数。每次调用函数时，计数器加一；函数返回后，计数器减一。当计数器达到上限时，新的调用会被拒绝，并报出递归错误。这个上限目前是二百层。

选择二百层的原因与实现有关。树遍历解释器在执行一次梦境函数调用时，会经过多层 C++ 函数，比如求值、函数调用、语句执行等。每一层都会占用一定的栈空间。如果把上限设得太高，在某些平台上，比如默认栈较小的 Windows 环境，可能会在 C++ 层面先发生栈溢出，导致程序崩溃，而不是给出清晰的错误信息。二百层是一个在多数平台上都安全的值。

这个限制的意义是保护性的。它让递归的失败变成一个可以被捕获和报告的错误，而不是一次难以诊断的崩溃。开发者在醒来后看到这个错误，就能立刻知道问题出在递归上，并且可以回到脚本中检查递归的终止条件。

错误信息中的"stack overflow in subconscious"是一个刻意的隐喻。在潜意识中，梦可能会无限地重复同一个场景，比如梦见自己反复走同一条楼梯。这种重复在脚本中就对应着递归没有终止。错误信息把技术问题和梦的意象联系在一起，让开发者在阅读时产生更直接的联想。

在实际使用中，遇到这个错误通常意味着递归的终止条件有问题。例如，一个计算阶乘的函数如果没有处理零的情况，就会无限地调用自己。解决的方法是检查基础情况是否正确，确保每次递归调用都会让问题变得更简单。

需要注意的是，这个限制只针对函数调用，不针对循环。使用 `while` 或 `for` 编写的无限循环不会触发递归错误，它只会一直运行下去，直到被外部中断。因此，写循环时同样需要确保有明确的退出条件。

如果确实需要更深的递归，目前的做法是改写为循环，或者把问题拆分为多个较小的部分。`dc` 没有提供修改上限的选项，这是为了保持行为的一致性。在梦境编程中，过深的递归本身就说明了梦的结构可能过于复杂，应当重新思考设计。

总之，调用深度限制是一个简单但有效的保护机制。它让递归的错误可以被及时发现，并用一个富有意象的信息提醒开发者回到问题的根源。
