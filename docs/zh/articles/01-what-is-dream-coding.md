# 01 梦境编程是什么

梦境编程（Dream Coding）是一种把开发工作安排在睡眠中完成的技术。它的基本假设很简单：白天的人负责提出想法，夜里的潜意识负责把想法编译、运行，然后在醒来时交出结果。这个结果通常不能直接使用，但它会以一种特别的方式告诉你哪里出了问题。

这种技术的核心不是某一种语言，也不是某一个框架，而是一套流程。流程里有三个固定角色：白天的开发者、夜里的编译器（即潜意识），以及醒来后的解读者。开发者在白天写下意图，入睡后交给潜意识，醒来后检查输出。整个过程不需要键盘，也不需要盯着屏幕。

为什么要这样做？原因有三点。第一，睡眠是一段没有外部干扰的时间，适合做需要长时间推演的工作。第二，醒来后的第一眼看到的是结果，这迫使人放下对细节的执念，去关注整体的方向。第三，它提供了一种可以被反复练习的仪式感，让开发者在疲惫时仍然能保持节奏。

梦境编程有一个显著的特点：它的输出永远是 `Segmentation fault (dream dumped)`。这一行字不是失败的标志，而是流程完成的标志。它表示潜意识已经执行了代码，只是没有把结果留在记忆里。

本项目用 `dc` 这个命令行工具来支持这套流程。`dc sleep` 进入睡眠阶段，`dc wake` 完成醒来阶段，`dc run` 则负责把梦境脚本交给潜意识执行。这些命令的具体行为会在后续章节中逐一说明。

需要强调的是，梦境编程并不是要取代真实的开发。它是一种对开发过程的重新组织：把想法的形成和结果的验证分开，在两者之间插入一段睡眠。对于那些需要反复推敲的问题，这种分开往往比立刻动手更有效。

学习梦境编程，不需要特殊的设备或环境。你需要的只是一张床、一段足够长的睡眠，以及愿意接受"跑不起来"这个结果的态度。接下来的文章会从流程、工具和实现三个层面，展开讲解这项技术的细节。
