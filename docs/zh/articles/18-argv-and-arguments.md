# 18 命令行参数与 argv

同一个梦境脚本往往需要接收不同的输入。比如一段用于计算斐波那契数列的脚本，可能希望每次运行时指定不同的项数。`dc` 通过全局变量 `argv` 支持这种需求。

`argv` 只在 `dc run` 中可用。当你执行 `dc run script.dc a b c` 时，文件路径之后的所有参数，也就是 `a`、`b` 和 `c`，会被收集到一个列表中，作为 `argv` 的值传给脚本。脚本可以像访问普通列表一样读取它：

```dc
print(len(argv));
for arg in argv {
    print(arg);
}
```

运行 `dc run script.dc a b c` 会输出 `3`，然后依次输出 `a`、`b` 和 `c`。注意，列表中不包含 `dc` 本身和 `run` 这两个词，也不包含脚本的路径。`argv` 只保存调用者真正想传给脚本的内容。

`argv` 中的每个元素都是字符串。如果你需要数字，要在脚本中用 `num` 或 `int` 进行转换。例如 `int(argv[0])` 会把第一个参数转换为整数。转换失败时，`num` 会报 `ValueError`，这与普通的字符串处理规则保持一致。

如果没有传入任何额外参数，`argv` 就是一个空列表。脚本应当考虑到这种情况，例如先检查 `len(argv)`，再决定如何使用它。这种防御性的写法，可以让脚本在参数缺失时给出有意义的提示，而不是直接出错。

`dc eval` 不支持 `argv`。它的代码是一段直接传入的字符串，没有对应的文件路径和额外参数的概念。如果需要在一行代码中使用参数，可以直接把参数写进字符串中。

从设计上看，`argv` 的存在让梦境脚本保持了通用性。同一个脚本可以在不同的场景中使用，而不需要为每个场景修改代码。这也符合梦境编程的精神：梦的内容可以随着输入而变化，但梦的结构保持不变。

最后需要提醒的是，参数是外部输入，因此在使用之前应当保持警惕。不要假设参数总是合法的，也不要把它直接用于敏感的操作。梦境脚本虽然运行在潜意识中，但它的输入仍然来自现实。
