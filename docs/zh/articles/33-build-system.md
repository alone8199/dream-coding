# 33 构建系统：CMake 与跨平台

`dc` 使用 CMake 作为构建系统。CMake 是一个生成原生构建文件的工具，它让同一份配置可以在 Linux、macOS 和 Windows 上使用。对于一个需要支持多平台的命令行工具来说，这一点非常重要。

项目的根目录下有一个 `CMakeLists.txt`，它定义了三个主要的目标。第一个是 `dc_core`，它是一个静态库，包含词法分析、语法分析、求值器、内置函数、标准库和命令行逻辑。第二个是 `dc`，它是可执行文件，只包含入口函数，并链接到 `dc_core`。第三个是测试程序，它们同样链接到 `dc_core`，用来验证各个部分的行为。

把核心逻辑放在静态库中，是为了让测试和可执行文件共享同一份代码。测试不需要复制实现，也不需要通过命令行间接调用。它们可以直接创建解释器，执行代码，检查结果。这种结构让测试更快，也更精确。

编译器的选项在配置阶段设置。在 GCC 和 Clang 上，项目启用了 `-Wall`、`-Wextra` 和 `-Wpedantic`，这些选项会检查常见的错误和不规范的写法。在 MSVC 上，项目使用 `/W4` 和 `/utf-8`。后者确保源码中的中文字符能被正确处理，这一点对于 `dc` 尤其重要，因为项目的注释和部分测试数据都包含中文。

C++ 标准被设定为 C++17。这个标准提供了 `std::variant`、`std::filesystem` 等现代特性，它们被用于值的表示和文件操作。CMake 同时关闭了编译器的扩展模式，以保证代码在不同编译器上的行为一致。

安装规则很简单：`dc` 可执行文件会被安装到 `bin` 目录中。CI 中的安装步骤会把它安装到工作区的 `dist` 目录，然后用该目录中的 `dc` 运行冒烟测试，确认安装后的程序可以正常工作。

CTest 集成是构建系统的一部分。项目通过 `include(CTest)` 启用测试支持，并在 `BUILD_TESTING` 打开时注册两个测试程序。开发者可以用 `ctest` 一次性运行所有测试，也可以只运行某个测试。

构建的基本流程是：用 `cmake -S . -B build` 生成构建目录，然后用 `cmake --build build` 编译，最后用 `ctest --test-dir build` 运行测试。这三条命令构成了本项目的标准工作流，也被写入了 CI 的配置中。

总之，CMake 让 `dc` 的构建保持简单且可移植。它的配置短小清晰，规则明确，使得任何一个开发者都可以在几分钟内从源码得到可运行的程序。
