# 25 函数与闭包

函数是梦境脚本组织逻辑的基本单位。`dc` 支持两种函数写法：一种是带名字的函数声明，使用 `fn` 加名字；另一种是匿名函数，直接用 `fn` 加参数列表写在表达式中。两者在运行时都是同一种值，区别只在于写法。

函数声明会把名字绑定到当前环境。例如 `fn add(a, b) { return a + b; }` 会在当前作用域中创建一个名为 `add` 的变量，它的值是一个函数。调用时写成 `add(1, 2)`，求值器会先查找 `add`，然后把参数按顺序绑定到 `a` 和 `b` 上，执行函数体，最后返回 `return` 指定的值。如果函数体没有 `return`，结果是空值。

匿名函数适合用在需要传递行为的地方。例如 `apply(fn(v) { return v * 10; }, 4)` 把一个乘以十的函数传给 `apply`，由它决定何时调用。匿名函数不需要名字，因此它的作用是临时的，通常只在一个表达式中使用。

闭包是函数的一个重要特性。函数在定义时会记录它所在的环境，这个环境就是它的闭包。之后，即使函数是在别处被调用，它仍然能访问定义时可见的变量。下面的例子展示了这一点：

```dc
fn make_counter() {
    let n = 0;
    return fn() {
        n = n + 1;
        return n;
    };
}
```

`make_counter` 执行结束后，它的局部变量 `n` 本应被销毁，但返回的匿名函数仍然持有对它的引用。每次调用返回的函数，`n` 都会增加一，并且结果会保留在同一个变量中。这就是闭包的典型用途：把状态封装在函数内部。

闭包的实现依赖于环境的引用计数。函数值持有定义时环境的共享指针，只要函数还存在，环境就不会被释放。这种设计让闭包的生命周期自然地跟随函数，不需要开发者手动管理。

函数调用时会检查参数的个数。如果传入的参数数量与声明不一致，求值器会报出 `TypeError`，并指出函数名和期望的参数数量。这个检查让参数错误在调用的那一刻就被发现，而不是在函数体中产生奇怪的行为。

需要注意的是，函数的参数是按值传递的，但由于列表和字典采用引用语义，传入的容器仍然可以被修改。如果你希望避免副作用，应当在函数内部复制容器，然后再进行操作。

从设计角度看，`dc` 的函数模型尽量保持简单。它没有默认参数、没有可变参数、也没有关键字参数。这些特性在大型语言中很有用，但对于梦境脚本来说，简单的位置参数已经足够。简单性让脚本的意图更容易被阅读，也让醒来后的解读更直接。
