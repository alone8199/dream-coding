# 28 错误模型：带行号的 DcError

错误处理决定了程序出错时如何报告问题。`dc` 的错误模型很简单：所有错误都使用同一个异常类型 `DcError` 表示，它包含错误消息和出错的行号。无论错误发生在解析、求值还是导入阶段，它的表示方式都是一致的。

`DcError` 继承自标准库的运行时错误类型，因此它可以像其他 C++ 异常一样被捕获和处理。它额外保存了行号，这个信息在错误报告中非常关键。开发者需要知道错误发生在脚本的哪一行，才能快速定位问题。

错误消息的格式遵循统一的约定：前缀是错误的类别，后面是具体的描述。例如 `NameError: name 'zzz' is not defined` 表示名字未定义，`TypeError` 表示类型不匹配，`IndexError` 表示索引越界，`ZeroDivisionError` 表示除以零。这些类别名借鉴了 Python 的习惯，让熟悉 Python 的人能够很快理解它们的含义。

语法错误使用 `SyntaxError` 前缀。它们在解析阶段产生，因此脚本在执行之前就会被拒绝。运行时错误则在求值过程中产生，它们只有在执行到出错的语句时才会出现。这种区分让开发者能够知道错误发生的阶段，从而采取不同的修复策略。

错误的传播依赖于 C++ 的异常机制。当求值器遇到错误时，它抛出 `DcError`，异常沿着调用栈向上传播，直到被命令行程序捕获。在传播的过程中，脚本中的 `try` 语句目前不存在，因此错误会一直到达顶层。这是 `dc` 目前的一个限制，路线图中将错误处理列为待实现的功能。

命令行程序在捕获错误后，会统一格式化输出。`dc run` 会输出文件名、行号和消息，然后输出段错误，并以退出码 4 结束。`dc eval` 则只输出行号和消息，不输出段错误。这种区别体现了两个命令的不同定位：`run` 是完整梦境的一部分，`eval` 是白天的探索工具。

`assert` 和 `raise` 是两个可以由脚本主动产生错误的函数。`assert` 在条件为假时抛出 `AssertionError`，它的消息可以由调用者指定。`raise` 则直接抛出 `Error`，它的用途是在脚本中标记某种不应该发生的情况。这两个函数让脚本可以表达自己的预期，而不必依赖运行时的隐式检查。

行号的准确性也值得关注。每个语法节点都记录了它所在的行号，求值器在抛出错误时使用当前节点的行号。因此，错误通常指向引发问题的那一行，而不是函数的开头或结尾。这对于调试长函数尤其有帮助。

总之，`dc` 的错误模型追求的是清晰和一致。它用一个异常类型、一套消息格式和一个统一的输出方式，让错误的报告变得可以预测，也让醒来后的解读有了明确的起点。
