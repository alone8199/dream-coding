# 21 递归下降语法分析

语法分析器的任务是把记号序列转换为语法树。`dc` 采用递归下降的方法实现它。这种方法的特点是：每一种语法结构对应一个函数，函数之间的调用关系与语法的嵌套关系一一对应。它直观、容易阅读，也便于调试。

语法分析器的入口是一个程序函数。它不断读取语句，直到遇到文件结束的记号，然后把所有语句收集到一个块节点中。块节点是整个程序的根，它的子节点就是顶层的语句。

语句的解析由一个分派函数完成。它根据当前记号的种类决定调用哪个子函数。遇到 `let` 时，解析 `let` 语句；遇到 `if` 时，解析条件语句；遇到 `fn` 且后面跟着名字时，解析函数声明；遇到左花括号时，解析代码块。如果都不匹配，就把它当作表达式语句处理。这种分派方式让每种语句的规则都保持独立。

表达式的解析是最复杂的部分。`dc` 按照优先级从低到高，依次实现赋值、逻辑或、逻辑与、相等、比较、加减、乘除、一元运算、后缀运算和基本项。每一层函数只负责自己的优先级，遇到更高优先级的运算时，就调用下一层函数。这种分层保证了乘法比加法先计算，而逻辑运算符的优先级最低。

赋值是一个特殊的情况。它的左边必须是一个可以被赋值的目标，比如变量、索引或成员访问。解析器会先按照普通的表达式解析左边，然后检查它的种类。如果不是合法的目标，就报出语法错误。这种检查让错误在解析阶段就被发现，而不是留到运行时。

后缀运算包括函数调用、索引和成员访问。它们可以连续出现，比如 `obj.items[0].name()`。解析器用一个循环处理它们，每遇到一个后缀，就把前面的表达式包装为新的节点。这种写法避免了递归带来的复杂性，同时保留了正确的结合顺序。

递归下降的一个优势是错误信息容易定位。当解析器遇到意外的记号时，它知道自己正处于哪一条语法规则中，因此可以给出具体的提示，比如"期望右括号，但找到了分号"。这种提示比通用的"语法错误"有用得多。

需要注意的是，递归下降也有局限。它难以处理左递归的语法，因此 `dc` 的运算符都用循环而不是递归来实现。它也对嵌套深度比较敏感，过深的表达式可能导致栈溢出。不过，对于梦境脚本来说，这些情况非常少见。

总之，递归下降是一种朴素但可靠的方法。它让语法分析器的每一行代码都能与语法规则对应起来，这种对应关系本身就是理解 `dc` 语法的最佳文档。
