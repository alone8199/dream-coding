# 30 注册原生函数

原生函数是用 C++ 实现、但可以被梦境脚本直接调用的函数。它们是 `dc` 扩展能力中最直接的一种：开发者不需要修改解释器本身，只需要在 C++ 代码中注册一个函数，就能让脚本使用它。

注册原生函数使用解释器的 `define_function` 方法。它接收两个参数：函数的名字，以及一个符合特定签名的函数对象。这个签名包含三个部分：解释器的引用、参数的列表、调用所在的行号。函数的返回值是 `Value` 类型，表示脚本中得到的结果。

下面是一个简单的例子。它注册了一个名为 `shout` 的函数，把传入的字符串后面加上三个感叹号：

```cpp
interp.define_function("shout", [](dc::Interpreter& in, std::vector<dc::Value>& args, int line) {
    if (args.size() != 1 || !args[0].is_str()) {
        throw dc::DcError("TypeError: shout() expects one string", line);
    }
    return dc::Value::str(std::get<std::string>(args[0].data) + "!!!");
});
```

这个函数先检查参数的数量和类型。如果不符合要求，它抛出 `DcError`，并把传入的行号附在错误中。这一点很重要：原生函数抛出的错误应当指向脚本中调用它的那一行，而不是 C++ 代码中的某一行。这样，脚本的开发者才能在自己的代码中找到问题。

参数的检查是原生函数的基本责任。`dc` 的解释器不会替原生函数做类型检查，因为它无法知道每个函数期望什么样的参数。因此，每个原生函数都需要自己判断参数的数量和类型，并在不符合要求时给出清晰的错误信息。

原生函数中可以使用解释器的输出流，例如 `in.out()`。如果函数需要打印信息，应当通过它输出，而不是直接写入标准输出。这样做的好处是，输出的目标可以被统一管理，也便于在测试中捕获。

原生函数还可以调用脚本中定义的函数。解释器提供了 `call` 方法，它接收一个函数值、参数列表和行号，然后执行调用并返回结果。这让原生函数可以与脚本协作，例如实现一个接收回调的排序函数。

注册的函数会被放在全局环境中，所有脚本都可以直接使用它。如果名字与内置函数冲突，注册的函数会覆盖内置函数。因此，在注册新函数之前，应当确认名字不会与已有的功能产生混淆。

总之，原生函数为 `dc` 提供了最简单的扩展方式。它不需要理解解释器的内部结构，只需要遵守参数和错误的约定，就能让脚本获得新的能力。
