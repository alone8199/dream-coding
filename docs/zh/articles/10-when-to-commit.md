# 10 提交的时机：为什么只在入睡时 commit

版本控制中的提交是一个确定性的动作。它把某个时刻的代码状态固定下来，写入历史，供他人审查和回溯。在传统开发中，提交通常发生在功能完成之后。梦境编程则要求提交只发生在入睡时，或者醒来后仍然记得梦的内容时。理解这条规则的理由，需要先看清提交的本质。

提交的本质是承诺。每一次提交都在说：这段代码是我认为正确的，我愿意为它负责。这种承诺在白天是合理的，因为白天的开发者有能力验证结果，也有条件修改。但在梦境编程中，代码是在睡眠中被推演的，它的正确性尚未得到检验。过早地承诺，会让仓库的历史充满未经验证的内容。

因此，梦境编程把提交的时机放在入睡时。这样做有两层含义。第一，入睡标志着白天工作的结束，此时开发者已经做完了当天能做的所有判断，适合做一次总结。第二，提交的内容应当是白天写下的脚本，而不是醒来后修改过的版本。这保证了提交的内容和梦的输入保持一致。

如果醒来后仍然记得梦的内容，并且认为其中有价值的部分，可以在醒来后做一次真正的提交。这次提交应当在commit message 中注明它来自梦境。本项目的 `CONTRIBUTING.md` 规定了类型前缀，例如 `dream:` 表示新增梦境，`nightmare:` 表示修复噩梦，也就是修复 bug。

强行提交是梦境编程最常见的违规行为之一。很多开发者在醒来后忍不住修改代码，然后立刻提交，以为这样可以保存进度。但这样做会让历史变得难以追溯：你无法分辨哪些改动来自梦，哪些来自白天的修补。

提交的时机还有一个实际的好处：它迫使开发者在入睡前做一次自我检查。问自己一个问题：我今天写下的内容，是否已经准备好交给潜意识？如果答案是否定的，那就应该回到白天的写作，而不是带着犹豫入睡。

总之，提交是一个需要慎重对待的动作。梦境编程把它放在一个特定的时刻，目的是让每一次提交都带着清醒的承诺，也让历史保留梦与现实之间的界限。
