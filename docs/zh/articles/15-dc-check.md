# 15 dc check：只看梦不跑

`dc check` 是一个只做语法检查的命令。它读取一个 `.dc` 文件，尝试解析其中的语法，然后输出结果，但不会执行任何代码。它的作用是在脚本运行之前，提前发现明显的书写错误。

用法非常简单：

```
$ dc check dreams/hello.dc
dreams/hello.dc: ok
```

如果语法正确，它会输出文件路径和 `ok`，并以退出码 0 结束。如果语法有误，它会输出文件名、行号和错误消息，并以退出码 4 结束：

```
$ dc check bad.dc
bad.dc:2: SyntaxError: unexpected ')'
```

这个检查只关心语法，不关心语义。也就是说，它能发现括号不匹配、字符串未闭合、关键字用在错误位置等结构问题，但它不会发现变量未定义、函数参数个数不对、除以零等问题。这些只有在运行时才会暴露。

`dc check` 之所以存在，是因为白天的写作很容易出现小错误。一个多余的括号，一个忘记闭合的字符串，都可能让整晚的睡眠白白浪费。在入睡前用 `dc check` 检查一遍，是一个低成本的保险。

在 CI 中，`dc check` 也被用来检查 `dreams/` 目录下的所有示例。流水线会对每个 `.dc` 文件运行一次检查，任何语法错误都会让构建失败。这保证了示例文件始终是可以被解析的，即使它们的语义还没有被完全验证。

需要注意的是，`dc check` 通过并不等于脚本能够正常运行。它只说明脚本的结构是合法的。一个语法正确的脚本仍然可能在运行时出错，比如引用了一个不存在的模块，或者在循环中做了无限递归。

从实现角度看，`dc check` 只调用了解析器，没有创建解释器，也没有执行任何语句。这让它的速度很快，也让它不会产生副作用。它是梦境编程中为数不多的、纯粹属于白天的验证手段。
