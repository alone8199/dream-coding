# 29 导入机制与模块缓存

模块让梦境脚本可以复用代码。`dc` 用 `import` 语句加载模块，它的查找规则、缓存方式和循环检查都有明确的约定。理解这些约定，可以帮助开发者组织多个脚本之间的依赖关系。

`import` 有两种写法。第一种是写一个名字，例如 `import math;`，它表示加载标准库或已注册的模块。第二种是写一个字符串路径，例如 `import "lib/greet.dc";`，它表示加载一个文件。两种写法的查找顺序是不同的，但它们都会把模块绑定到当前作用域中的一个名字上。

对于名字形式的导入，求值器首先检查模块缓存。如果这个模块已经被加载过，就直接返回缓存的结果。如果没有缓存，它会查找注册的模块工厂。标准库中的 `math` 和 `dream` 就是这样提供的。注册的模块优先于文件模块，这意味着同名的 `.dc` 文件不会覆盖内置模块。

对于路径形式的导入，求值器会把路径与当前文件所在的目录拼接，得到完整的文件位置。如果路径没有以 `.dc` 结尾，它会自动补上后缀。文件存在时，它读取并解析文件内容，然后在一个独立的环境中执行。

模块的绑定名字取自文件名，去掉目录和后缀之后的部分。例如 `import "lib/greet.dc";` 会把模块绑定到名字 `greet` 上。这意味着，如果两个不同目录下的文件同名，它们会在各自的作用域中产生相同的绑定名，需要用不同的导入位置来区分。

模块中的所有顶层名字，只要不以下划线开头，都会成为模块对象的成员。以下划线开头的名字是私有的，它们可以在模块内部使用，但不会被导出。这个约定与 Python 的习惯一致，它让模块的公共接口可以通过命名来表达，而不需要额外的声明。

模块只会执行一次。第一次导入时，求值器会执行模块的代码，并把结果缓存起来。之后再导入同一个模块，直接使用缓存的对象，不会重新执行。这种缓存保证了模块中的副作用只发生一次，也避免了重复的开销。

循环导入是一种需要防范的情况。如果模块 A 导入模块 B，而模块 B 又导入模块 A，就会形成一个无限的依赖链。`dc` 通过一个导入栈来检测这种情况。当发现一个模块正在被加载时又被请求，它会报出 `ImportError: circular import`，并指出模块的名字。

找不到模块时，导入会报出 `ImportError: no module named`，并给出模块的名字。这个错误通常意味着路径写错了，或者文件不在预期的目录中。由于文件路径是相对于当前文件的，移动文件之后，相对路径可能需要相应地修改。

总之，导入机制用一套简单的规则，支撑了模块的复用、缓存和隔离。它的设计目标是可预测：开发者应当能够仅凭规则就推断出导入的结果。
