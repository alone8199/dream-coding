# 22 语法树的单一节点结构

语法树是语法分析的产物，也是求值器的输入。在很多解释器中，每一种语法结构都对应一个独立的类，比如加法节点、函数调用节点、条件节点各自有一个类。`dc` 的做法不同：所有节点都使用同一个结构体，靠一个种类字段来区分它们的含义。

这个结构体的定义非常简单。它包含一个种类字段，表示节点是数字、字符串、标识符、函数调用、条件语句，还是其他类型。它包含一个行号，用于错误报告。它包含一个文本字段，用于保存标识符名、运算符或字符串内容。它包含一个数字字段，用于保存数字字面量或布尔值。它包含一个名字列表，用于保存函数的参数名。它还包含一个子节点列表，用于保存子表达式或子语句。

这种设计的好处是简单。整个语法树只需要一种类型，遍历和处理的代码都可以集中在一个地方。新增一种语法结构时，只需要在种类枚举中加一个值，然后在解析器和求值器中各加一个分支，不需要定义新的类，也不需要处理复杂的继承关系。

代价是类型安全性较弱。编译器无法检查某个节点是否拥有正确数量的子节点，也无法保证文本字段在某些种类中一定有值。`dc` 通过约定来弥补这一点。例如，二元运算节点总是有两个子节点，函数调用节点的第一个子节点是被调用的对象，其余子节点是参数。这些约定写在注释中，也体现在解析器的实现里。

每个种类的节点都有明确的语义。块节点表示一组语句，它的子节点按顺序执行。条件节点的子节点依次是条件、分支和可选的 else 分支。循环节点的子节点是条件和循环体。函数声明节点保存函数名、参数名和函数体。这些约定让求值器可以根据种类直接取出需要的字段。

节点使用共享指针管理内存。这样做的原因是，函数值需要持有函数体的引用，而函数体的生命周期可能超过定义它的语句。共享指针保证了即使语法树的某些部分被函数捕获，它们也不会被提前释放。

从维护的角度看，单一节点结构要求开发者养成良好的注释习惯。每个种类的字段含义都应当在枚举处说明，这样后来者才能快速理解。`dc` 的 `ast.hpp` 就是这样做的：它在每个种类旁边注明了子节点的含义。

总之，单一节点结构是一种以简单换取灵活性的设计。它不是唯一正确的选择，但对于 `dc` 这样规模的解释器，它让代码的总量保持在可以被一个人完整理解的范围内。
