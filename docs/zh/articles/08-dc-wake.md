# 08 醒来：dc wake 与 segfault 的含义

`dc wake` 是梦境编程的醒来命令。运行它会输出两行内容：

```
$ dc wake
Waking up...
Segmentation fault (dream dumped)
```

第一行表示醒来的过程开始了。第二行是整个流程中最重要的一行：`Segmentation fault (dream dumped)`。它的字面意思是段错误，并且梦被倾倒了。在梦境编程中，这一行不是失败的标志，而是流程完成的标志。它表示潜意识已经执行了代码，结果已经产生，只是这些结果不会以可读的形式留在记忆里。

为什么选择段错误这个形式？段错误在传统开发中是最令人沮丧的错误之一：程序突然崩溃，没有给出清晰的原因。梦境编程借用了这个形象，把它变成一种仪式性的结果。每个醒来的人都会看到同样的一行字，它提醒你：你醒来后面对的不是一个能用的程序，而是一个需要解读的梦。

`dc wake` 本身并不检查梦的内容。它不会读取任何脚本，也不会判断执行是否成功。它输出的永远是同样的两行，这是它的设计。这种固定输出让醒来的仪式变得可以预期，也让开发者不必在醒来后立即面对复杂的信息。

在脚本层面，同样的输出也可以由梦境脚本主动产生。标准库中的 `dream` 模块提供了 `wake()` 函数，调用它会打印同样的段错误信息。这意味着，一个梦境脚本可以用代码显式地宣告自己的醒来。

需要注意的是，醒来后的正确反应是接受这一行输出，而不是立刻去查找错误。如果你在醒来后执行 `dc run` 得到了报错，那说明报错来自脚本本身，而不是梦。`dc run` 出错时同样会输出段错误，但它前面会带上文件名和行号，两者可以区分。

醒来还有一个隐含的步骤：解梦。开发者应当在醒来后的一段时间里，回想梦里残留的印象，并把它们记录下来。这个步骤在下一篇文章中会详细讨论。

总之，`dc wake` 的价值在于它标记了醒来的时刻，并用一个固定的仪式把结果交还给开发者。它的输出简单、固定、有象征意义，正是这些特点让醒来的过程变得可以被反复练习。
