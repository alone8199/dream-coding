# 31 注册 C++ 模块

[中文](./31-native-modules.md) | [English](./31-native-modules.en.md)

如果一组原生函数需要一起使用，把它们分别注册到全局环境中会显得杂乱。`dc` 提供了另一种方式：把它们组织成一个模块。模块在脚本中用 `import` 加载，然后通过点号访问其中的函数，就像标准库中的 `math` 模块一样。

注册模块使用解释器的 `register_module` 方法。它接收两个参数：模块的名字，以及一个工厂函数。工厂函数在模块第一次被导入时调用，它的返回值应当是一个字典，字典中的每一项都会成为模块的成员。

下面的例子注册了一个名为 `clock` 的模块，它包含一个版本号和一个获取当前时间的函数：

```cpp
interp.register_module("clock", [](dc::Interpreter&) {
    dc::Value m = dc::Value::dict();
    auto& items = std::get<dc::DictPtr>(m.data)->items;

    items["version"] = dc::Value::str("1.0");
    items["now"] = dc::make_native("now", [](dc::Interpreter&, std::vector<dc::Value>&, int) {
        return dc::Value::num(static_cast<double>(std::time(nullptr)));
    });
    return m;
});
```

在脚本中，可以这样使用它：

```dc
import clock;
print(clock.version, clock.now() > 0);
```

工厂函数的结果会被缓存。第一次导入时执行工厂函数，之后再次导入同一个模块，直接返回缓存的对象。这保证了模块的初始化只发生一次，也让模块中的状态在多次导入之间保持一致。

模块的成员可以是任何值，包括数字、字符串、列表、字典和函数。普通的值适合作为常量，比如版本号；函数适合作为模块的行为，比如获取时间。模块甚至可以包含其他模块，只要把它们放进字典中即可。

注册模块与编写 `.dc` 模块在使用上是一样的。脚本不需要知道模块的实现来自 C++ 还是来自梦境脚本，它只需要按照名字和字段来访问。这种一致性让扩展变得透明，也让团队可以根据需要选择合适的实现方式。

需要注意的是，注册的模块与标准库中的模块同名时，会覆盖标准库的版本。原因在于两者共用同一张注册表，后注册的会替换先注册的。文件模块的查找顺序排在最后，只有注册表中找不到时才会去读取 `.dc` 文件。因此，给模块起名时应当避免使用 `math`、`dream` 这样的已有名字，除非确实想替换它们。

在设计模块时，建议把相关的功能放在同一个模块中，并为每个函数写清楚参数和返回值的约定。模块是脚本与 C++ 代码之间的边界，清晰的边界能让两边的维护者都更容易理解对方的意图。

总之，注册模块是一种把 C++ 功能组织给脚本使用的正式方式。它的核心只有一个约定：工厂函数返回一个字典。遵守这个约定，就能让任何 C++ 代码成为脚本可以导入的模块。
