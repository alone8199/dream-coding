# 07 入睡：dc sleep 与七小时的下限

[中文](./07-dc-sleep.md) | [English](./07-dc-sleep.en.md)

`dc sleep` 是梦境编程的入睡命令。它的作用是标记一段睡眠的开始，并检查睡眠时长是否满足最低要求。它本身不会执行任何脚本，真正的执行发生在你睡着的时候。

命令的基本用法很简单：

```
$ dc sleep
Entering REM cycle...
zzz... (8h)
```

如果不指定时长，默认是八小时。也可以显式传入小时数，例如 `dc sleep 7.5`。时长必须是非负数字，否则命令会以退出码 2 结束，并给出错误提示。

最关键的规则是七小时的下限。如果传入的时长少于七小时，命令会输出 `TimeoutError: sleep too short`，并以退出码 1 结束：

```
$ dc sleep 4
TimeoutError: sleep too short (4h < 7h)
```

这条规则的理由是：一个完整的睡眠周期大约需要九十分钟，而 REM 阶段通常出现在后半夜。时长不足，梦境往往会在最有价值的阶段被截断，产生的结果缺少连贯性。七小时是一个经验性的下限，它保证大脑至少能完成几个完整的周期。

`dc sleep` 的输出分为两行。第一行 `Entering REM cycle...` 表示进入了快速眼动阶段，第二行显示睡眠时长。这两行输出没有实际的计算意义，它们的作用是给开发者一个明确的仪式感：睡眠已经开始，白天的工作可以结束了。

从实现角度看，`dc sleep` 的逻辑非常简单：解析参数，检查数值是否合法，比较时长与下限，然后输出结果。它不会修改任何文件，也不会启动后台进程。这种简单性是有意设计的。睡眠本身是一个被动的过程，命令也应当保持被动。

在实际使用中，有几个常见的误区。第一个误区是把 `dc sleep` 当成真正的睡眠开关，以为运行它就会让人入睡。实际上，入睡是身体的事情，命令只是一个标记。第二个误区是为了凑时长而反复运行命令。每次运行都会输出一次进入 REM 的提示，但它不会累加时长。第三个误区是在睡眠中途醒来后仍然认为梦境已经完成。

`dc sleep` 的价值在于它把睡眠变成了一个可以被记录的动作。它让开发者在每一次入睡时都有一个明确的起点，也让整个流程的节奏变得清晰。
