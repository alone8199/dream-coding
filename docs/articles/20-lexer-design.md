# 20 词法分析器的设计

[中文](./20-lexer-design.md) | [English](./20-lexer-design.en.md)

词法分析器是 `dc` 处理源码的第一步。它的任务是把一个字符串切分成记号序列，每个记号都带有种类、文本内容和所在行号。这一步不关心语法是否正确，只关心每个片段属于哪一类。

`dc` 的记号分为几类。第一类是标识符和关键字。标识符由字母、下划线和数字组成，但不能以数字开头。关键字，比如 `let`、`fn`、`if`、`while`、`import` 等，会被识别为专门的记号种类，而不是普通标识符。第二类是数字，支持整数和小数，统一用双精度浮点数表示。第三类是字符串，用双引号包围，支持 `\n`、`\t`、`\"` 等转义字符。第四类是符号，包括括号、逗号、分号、点号，以及各种运算符。

有几个细节值得单独说明。首先，标识符允许使用非 ASCII 字符。词法分析器把所有字节值大于等于 0x80 的字符都视为标识符的一部分，这让中文变量名成为可能。这个设计的代价是，它不会对变量名做 Unicode 层面的规范化，但对于梦境编程来说，这种简单的规则已经足够。

其次，注释有两种写法：以井号开头，或者以双斜线开头，直到行尾为止。这种双重支持是为了让不同习惯的开发者都能顺畅地书写。注释会在词法分析阶段被直接跳过，不会产生任何记号。

第三，运算符的识别采用两步法。词法分析器先检查两字符的运算符，比如等于号、不等号、小于等于号，以及逻辑与、逻辑或；如果不匹配，再检查单字符的运算符。这样可以保证 `<=` 被识别为一个整体，而不是 `<` 和 `=` 的组合。

第四，字符串中的换行是不被允许的。如果遇到未闭合的字符串，词法分析器会立即报出语法错误，并指出字符串开始的行号。这种严格的规则能让错误尽早被发现，而不是在后面的语句中产生难以理解的连锁反应。

词法分析器的输出是一个数组，最后一个元素总是表示文件结束的记号。这种设计让语法分析器可以安全地向前查看，而不必担心越界。

整个词法分析器的实现非常直接，它只有一次从左到右的扫描，没有回溯，也没有状态机之外的复杂逻辑。这种简单性使它很容易测试和维护，也是 `dc` 能够在各个平台上快速构建的原因之一。
