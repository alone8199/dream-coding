# 19 整体架构：从源码到潜意识

[中文](./19-architecture-overview.md) | [English](./19-architecture-overview.en.md)

`dc` 的实现可以分成几个清晰的层次。从一个 `.dc` 文件进入，到结果输出为止，它依次经过词法分析、语法分析、语法树、求值器和运行时的值。这一篇概述整个流程，后续的文章会逐一展开每个环节。

整个流程的起点是源文件。`dc run` 读取文件内容，把它作为字符串交给解释器。解释器首先调用词法分析器，把字符串切分为记号（token）。记号是最小的有意义单位，比如关键字、标识符、数字、字符串和运算符。词法分析器不理解结构，它只负责识别每个片段是什么。

接下来，语法分析器读取记号序列，按照语法规则构造语法树。语法树是一棵由节点组成的树，每个节点代表一个语句或表达式。比如一个函数调用会生成一个 `Call` 节点，它的子节点分别是被调用的函数和参数。语法分析采用递归下降的方法，每一种语法结构对应一个函数。

语法树生成之后，求值器开始工作。它从根节点开始，递归地遍历每个节点，并根据节点的类型执行相应的操作。例如遇到 `Let` 节点时，求值器会在当前作用域中定义一个变量；遇到 `Binary` 节点时，它会先计算左右两边的值，再执行运算。求值器维护一个作用域链，用来查找变量。

求值器处理的数据是运行时的值。这些值可以是空值、布尔值、数字、字符串、列表、字典或函数。它们统一用一个 `Value` 类型表示，内部使用标准库的变体类型存储不同的种类。列表、字典和函数采用引用语义，这意味着多个变量可以指向同一个对象。

运行的结果通过标准输出显示。脚本中的 `print` 会直接写入输出流，错误则会被捕获，并附上行号信息，最后由命令行程序决定如何显示和返回退出码。

这个架构的每一层都尽量保持独立。词法分析器不知道语法，语法分析器不知道运行时，求值器不关心命令行。这种分层让每一部分都可以单独测试，也让扩展变得可能：如果想增加新的内置函数，只需要修改标准库，而不必改动解析逻辑。

值得一提的是，整个实现都是树遍历解释器。它不生成机器码，也不做优化。这种选择牺牲了速度，但换来了简单和可读性。对于梦境编程这样的技术来说，清晰的结构比执行效率更重要，因为开发者需要理解梦是如何被推演的。
