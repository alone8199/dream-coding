# 02 From Vibe Coding to Dream Coding

To understand where dream coding stands, look at its predecessor. One of the most popular development styles of recent years is vibe coding: developers stop thinking through code line by line, and instead describe a rough feeling, let AI generate the implementation, and then judge by running it whether the direction is right. Vibe coding is very efficient, but its output is often code that runs yet is hard to maintain. People half-jokingly call such results a "shit mountain" (屎山), the slang for tangled, unmaintainable code.

Vibe coding puts its attention on generation speed. The developer's main actions are to state a feeling, wait for output, and then state a new feeling. The loop is fast, but every round requires a person to be present, and that person's attention stays active the whole time. This is exactly the problem: active attention keeps interrupting deduction and lets people lose their way in the details.

Dream coding follows the same direction and takes one step further. It asks: what happens if the developer is not there at all? The answer is that the code gets "run" during sleep and produces a version that cannot be used directly. The value of that version lies not in whether it runs, but in revealing the parts the developer did not think through during the day.

The differences between the two can be summarized along several dimensions. In terms of action, vibe coding requires continuous input, while dream coding requires only one. In terms of output, vibe coding produces runnable code, while dream coding produces results to reflect on. In debugging, vibe coding relies on error messages and AI patching, while dream coding asks the developer to understand the lingering impressions left after waking. In terms of destination, the former often ends at Stack Overflow, while the latter ends in the interpretation of the dream.

This comparison does not mean that dream coding is better than vibe coding. The two solve different problems. When you need to verify an idea quickly, vibe coding is the better fit. When you need an idea to settle and are willing to accept a period of waiting, dream coding is the better fit.

From an engineering perspective, dream coding also offers an idea worth borrowing: stretch the time between "generation" and "verification." Often we write bad code because generation and verification are squeezed into the same time window, leaving no room for thought. Sleep provides that room.

Therefore, dream coding can be seen as a complement to vibe coding, not a replacement for it. It reminds us that the speed of development is not always the faster the better. Some conclusions need time to take shape, and sleep happens to be the quietest, least disturbed stretch of time.
